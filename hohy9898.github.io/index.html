트러블슈팅 · 답변 정확도 72% → 97%

문제
보유 도서로 답할 수 있는 질문에도 틀린 답이 나왔습니다. 29문항을 3회씩 채점한 결과 통과율은 72%(63/87)였습니다.
원인
처음에는 검색 품질 문제라고 보고 하이브리드 검색을 붙였지만 64%로 차이가 없었습니다. 실패한 답변을 다시 보니, 4B 모델이 툴을 아예 부르지 않고 답하거나 "가장 비싼", "넘는" 같은 표현을 검색 파라미터로 잘못 옮기고 있었습니다.
해결
도서 질문은 반드시 툴을 먼저 부르도록 규칙을 넣고, 검색 결과 수를 10 → 30으로 늘리고, 저자 이름 오타를 허용했습니다. 모델이 헷갈리던 정렬·가격 파라미터 설명도 구체적으로 고쳤습니다.
결과
통과율이 72% → 90% → 97%(84/87)로 올랐습니다. 작은 모델은 검색보다 툴 호출 판단에서 더 많이 틀린다는 것을, 추측이 아니라 측정으로 확인했습니다.

트러블슈팅 · 배포된 사이트에서 API 키 노출

문제
배포된 사이트의 JS 파일을 열면 OpenAI API 키가 그대로 보였습니다.
원인
브라우저에서 OpenAI를 직접 호출하는 구조였고, VITE_로 시작하는 환경 변수는 빌드할 때 JS 파일에 그대로 들어갑니다.
해결
키를 폐기하고 OpenAI 호출을 Netlify Function으로 옮겼습니다. 프롬프트를 통째로 받으면 누구나 함수를 무료 OpenAI 프록시로 쓸 수 있으므로, 브라우저는 질문만 보내고 부산 데이터를 붙여 프롬프트를 만드는 일은 서버가 하도록 했습니다. 질문 길이는 500자로 제한했습니다.
결과
키는 서버 환경 변수에만 남고, 함수는 이 서비스의 질문에만 답합니다. 비밀 값은 서버에 두고, API는 "다른 용도로 쓰일 수 있는가"까지 따져 설계해야 한다는 것을 배웠습니다.
