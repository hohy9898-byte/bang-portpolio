# 부산, 축제 어디까지 가는 거예요?

부산 시민과 관광객이 축제 정보를 챗봇에게 묻고, 게시판에서 후기를 나누는 지역 축제 커뮤니티다. SSAFY 팀 프로젝트로 만들었다.

- 기간: 2026.07 ~ 2026.10
- 인원: 3명 (팀 윈도우 98) - 방호준(조장, 커뮤니티 게시판), 이승진(메인 페이지), 이승우(챗봇)
- 기술: Vue 3, Vite, Netlify Functions, OpenAI API, 한국관광공사 TourAPI
- 배포: https://site-make.netlify.app/

## 주요 기능

- 홈: 한 달 안에 열리는 축제 소개, 축제 캘린더, 오늘의 인기글, 챗봇 검색창
- 챗봇: TourAPI의 부산 숙박·축제·관광지 데이터를 근거로 `gpt-5-mini`가 답한다.
- 커뮤니티 게시판 (내 담당)
  - 축제, 숙박, 물건 찾기, 자유 카테고리
  - 비밀번호로 수정·삭제·공유 확인
  - 추천 10개 이상은 인기글, 비추천이 많은 글은 분리수거 탭으로 자동 분류
  - 북마크, 해시태그, 이미지 첨부, 검색, 페이지네이션, 글 공유 링크

## 내가 맡은 부분

조장으로 일정과 기능 범위를 정리했고, 커뮤니티 게시판을 처음부터 끝까지 만들었다. 홈의 "오늘의 인기글"이 게시판 데이터를 쓰도록 연결한 것도 내 작업이다. 발표 후에는 챗봇 API 키가 브라우저에 노출되던 구조를 서버리스 함수로 옮겨 고쳤다.

## 고민한 점

### 브라우저에 API 키가 그대로 보이는 문제

처음에는 브라우저에서 OpenAI를 바로 호출했고, 키는 `VITE_OPENAI_API_KEY` 환경 변수에 넣었다. 그런데 `VITE_`로 시작하는 변수는 빌드할 때 JS 파일에 그대로 들어가서, 배포된 사이트의 JS를 열면 키가 보였다.

키를 폐기하고 OpenAI 호출을 Netlify Function(`netlify/functions/chat.mjs`)으로 옮겼다. 이때 프롬프트를 통째로 받는 함수로 만들면 누구나 이 함수를 공짜 OpenAI 프록시로 쓸 수 있다. 그래서 브라우저는 질문만 보내고, 부산 데이터를 붙여 프롬프트를 만드는 일은 서버에서 하도록 했다. 질문 길이도 500자로 제한했다.

### 챗봇 응답이 느린 문제

질문할 때마다 7개 카테고리 데이터를 전부 프롬프트에 넣다 보니 답이 늦게 왔다. 질문에 "호텔", "숙소"가 있으면 숙박 데이터만 넣는 식으로 키워드에 맞는 카테고리만 골라 넣고, 카테고리마다 길이도 잘랐다. 맞는 키워드가 없을 때만 전체를 넣는다.

### 기능을 추가할 때마다 예전 글이 깨지는 문제

게시글은 localStorage에 저장했는데, 태그나 북마크 기능을 추가하고 나면 그 전에 저장된 글에는 해당 필드가 없어서 화면에서 에러가 났다. 글을 불러올 때 `normalizePosts()`에서 빠진 필드를 기본값으로 채우도록 했고, 저장된 값이 깨져 있으면 빈 목록으로 시작하게 했다.

## 실행 방법

```bash
npm install
cp .env.example .env   # OPENAI_API_KEY 입력
npx netlify dev        # Vite와 함수를 같이 실행 (http://localhost:8888)
```

`npm run dev`만 실행하면 챗봇 API(`/api/chat`)가 뜨지 않는다. 배포할 때는 Netlify 사이트 설정의 Environment variables에 `OPENAI_API_KEY`를 넣는다.

## 아쉬운 점

- 게시글이 브라우저(localStorage)에만 저장돼서 다른 사람과 글이 공유되지 않는다. 실제 커뮤니티가 되려면 백엔드와 DB가 필요하다.
- 비밀번호를 평문으로 저장하고, 추천 제한도 브라우저 기준이라 저장소를 지우면 다시 누를 수 있다. 서버로 옮기면서 해시 저장과 서버 검증으로 바꾸고 싶다.
- 이미지를 Data URL로 저장해서 localStorage 용량(약 5MB)이 금방 찬다.

## 배운 점

- 프론트엔드 환경 변수는 숨겨지지 않는다. 비밀 값은 반드시 서버 쪽에 둬야 한다는 걸 배포 후에야 알았다.
- 서버 API를 만들 때는 "누가 이걸 다른 용도로 쓸 수 있나"까지 생각해야 한다.
- 게시판을 만들면서 데이터 구조가 바뀔 때 기존 데이터를 어떻게 살릴지 고민해야 한다는 걸 느꼈다. 이건 DB를 쓸 때의 마이그레이션 문제와 같다.
